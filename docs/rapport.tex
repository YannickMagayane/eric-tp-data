\section{Architecture du Syst\`eme}
L'infrastructure repose sur une orchestration Docker reproductible articul\'ee autour de quatre services isol\'es :
\begin{itemize}
    \item \textbf{Traefik v3} : unique reverse proxy routant les flux HTTP vers le tableau de bord analytique (\texttt{metabase.localhost}).
    \item \textbf{Conteneur \texttt{dev} (Debian Bookworm / Python 3.14)} : image multi-stage ex\'ecut\'ee sous un utilisateur non-root (\texttt{appuser}, UID 1000), embarquant les filtres UNIX (\texttt{bash}, \texttt{sed}, \texttt{gawk}, \texttt{sort}, \texttt{uniq}, \texttt{jq}), \texttt{gnuplot}, \texttt{shellcheck} et la biblioth\`eque Python \texttt{iragi} (\texttt{0.6.4}).
    \item \textbf{PostgreSQL 16 (\texttt{db})} : stockage relationnel typ\'e avec contraintes d'int\'egrit\'e m\'etier et contr\^oles de sant\'e (\texttt{pg\_isready}).
    \item \textbf{Metabase (\texttt{dashboard})} : visualisation interactive connect\'ee \`a PostgreSQL.
\end{itemize}

\section{Acquisition des Donn\'ees et Gouvernance par Iragi}
Un g\'en\'erateur reproductible (\texttt{scripts/etl/generate\_data.py}) produit les trois sources exig\'ees dans \texttt{data/raw/} (\texttt{livraisons.csv}, \texttt{livreurs.json}, \texttt{access.log}) en injectant un volume calibr\'e de doublons, lignes vides, espaces parasites et hors-bornes m\'etier.

En compl\'ement des pipelines UNIX natifs, le module \texttt{iragi} assure :
\begin{enumerate}
    \item Le calcul explicable du score de qualit\'e sur 100 avant et apr\`es nettoyage via \texttt{iragi.scan} et \texttt{iragi.compare\_scans}.
    \item La validation contractuelle via \texttt{iragi.DataContract} et l'isolement en \emph{Dead-Letter Queue} (\texttt{quarantine\_livraisons.csv}) via \texttt{iragi.auto\_clean}.
    \item La r\'econciliation inter-sources entre \texttt{livraisons.csv} et les traces HTTP \texttt{/api/livraisons/LIV-<id>} de \texttt{access.log} via \texttt{iragi.reconcile}.
\end{enumerate}

\section{Description des Pipelines UNIX}
La Phase 2 impl\'emente une cha\^ine modulaire strictement conforme \`a la philosophie des filtres UNIX (\texttt{LC\_ALL=C}, \texttt{set -euo pipefail}) :
\begin{enumerate}
    \item \textbf{Nettoyage (\texttt{scripts/etl/clean\_data.sh})} : suppression des lignes vides et normalisation des espaces via \texttt{sed}, d\'eduplication exacte par \texttt{sort | uniq}, validation des types, dates ISO et bornes m\'etier en \texttt{awk} (atteignant un score certifi\'e de \texttt{100.0/100} sous \texttt{iragi.scan}), extraction de \texttt{livreurs.json} via \texttt{jq} et structuration de \texttt{access.log}.
    \item \textbf{Transformation (\texttt{scripts/etl/transform\_data.sh})} : calcul des colonnes d\'eriv\'ees (\texttt{speed\_kmh}, \texttt{year\_month}) en \texttt{awk}, jointure relationnelle par ville avec la flotte de livreurs via la commande UNIX \texttt{join}, agr\'egations multi-axes (\texttt{group by} ville, mois, statut) et export JSON typ\'e avec \texttt{jq}.
    \item \textbf{Analyse (\texttt{scripts/analysis/analyze\_data.sh})} : calcul exact de la moyenne, m\'ediane, minimum, maximum et \'ecart-type, g\'en\'eration d'un histogramme fréquentiel des dur\'ees en \texttt{awk}, calcul du coefficient de corr\'elation de Pearson $r$, consolidation des anomalies (donn\'ees brutes, vitesses extr\^emes, codes HTTP \texttt{4xx}/\texttt{5xx}) et pr\'eparation des fichiers \texttt{.dat} pour \texttt{gnuplot}.
    \item \textbf{Orchestration (\texttt{scripts/etl/run\_pipeline.sh})} : ex\'ecution s\'equentielle avec capture d'erreurs (\texttt{trap ERR}), journalisation horodat\'ee (\texttt{pipeline.log}) et rapport d'\'etat JSON (\texttt{pipeline\_status.json}).
\end{enumerate}

\section{Difficult\'es Rencontr\'ees et Solutions}
\begin{itemize}
    \item \textbf{Permissions sur volumes Docker} : r\'esolues par l'alignement UID/GID 1000 de \texttt{appuser} dans l'image multi-stage.
    \item \textbf{D\'eterminisme des filtres UNIX} : verrouill\'e par \texttt{LC\_ALL=C} et \texttt{set -euo pipefail} dans tous les scripts shell.
\end{itemize}
